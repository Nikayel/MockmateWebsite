Run untrusted JS/TS code securely via Native Web Workers

Complete

Sprint Status: Shipped to Main

We created the JS sandbox worker, integrated standard DSA helper classes/methods, implemented support for multi-file workspace scenario imports (CommonJS mocks), and built a server-side route for TypeScript compilation.

📋 Sprint 1 Deliverables

Architectural Decisions

💡
CommonJS Path Resolvers
Workspace scenarios reference relative paths (e.g. ../state or ./controller). The worker maps file paths dynamically and wraps modules with a mock require wrapper to resolve these relative paths seamlessly without node.
⚙️
No Local TS Compiler in Worker
Importing a compiler like SWC or TypeScript directly inside the Web Worker adds ~10MB+ bundle sizes to the client download. Instead, a lightweight server endpoint (/api/transpile) handles transpilation-only requests, keeping execution entirely client-side.
🔍 Code Explanations
public/workers/js-sandbox-worker.js 
// Intercept console.log to capture prints during sandbox run
console.log = function (...args) {
  logs.push({
    type: 'log',
    message: args.map(a => typeof a === 'object' ? JSON.stringify(a) : String(a)).join(' '),
    timestamp: Date.now()
  });
};

// Inject CommonJS Mock Require inside the worker global scope
const assertMock = {
  ok: (val, msg) => { if (!val) throw new Error(msg || "Expected truthy"); },
  strictEqual: (a, b, msg) => { if (a !== b) throw new Error(msg); },
  deepStrictEqual: (a, b, msg) => { /* Deep comparison */ }
};
cache['node:assert/strict'] = { exports: assertMock };

function requireModule(path, currentDir) {
  const resolved = resolvePath(currentDir, path);
  if (cache[resolved]) return cache[resolved].exports;
  
  const wrapper = new Function('exports', 'require', 'module', moduleCode);
  wrapper(module.exports, localRequire, module);
  return module.exports;
}
The worker captures console methods, defines assertion methods natively to replace Node's assert dependencies, and wraps code declarations inside custom Function instances to support modular multi-file require flows.
app/api/transpile/route.ts 
import ts from "typescript"

export async function POST(request: NextRequest) {
  const { code } = await request.json()
  
  const transpiled = ts.transpileModule(code, {
    compilerOptions: {
      module: ts.ModuleKind.CommonJS,
      target: ts.ScriptTarget.ES2020,
      jsx: ts.JsxEmit.React,
      esModuleInterop: true,
    },
  })

  return NextResponse.json({ code: transpiled.outputText })
}
Compiles TS/JSX input into client-runnable CommonJS modules. This execution is completely safe on the server because the transpiler only compiles text syntax (no code gets run on the server context).

Sprint 2: Client-Side Python Wasm (Pyodide)

Run untrusted Python code inside WebAssembly sandboxes

Planned
📋 Sprint 2 Deliverables

Proposed Architectural Decisions

🐍
Pyodide Wasm Engine
Pyodide compiles a full Python 3 runtime into WebAssembly. This supports standard libraries (e.g. heapq, math, collections) needed for DSA, without any server-side dependencies.
⚡
Singleton Worker Lifecycle
Downloading and initiating Wasm takes ~2 seconds. By keeping a persistent Web Worker active, subsequent executions run instantly. If code hangs, we terminate and replace the worker.
