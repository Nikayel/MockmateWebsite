# System Design Interactivity Plan

> Produced by the sd-interactivity-council workflow on 2026-07-23 (6 per-level auditors over all 12 levels,
> 3 perspective judges: learning science / staff engineering / product-pitch, 1 synthesizer; 10 agents, all clean).
> This plan is BINDING for the /loop retrofit iterations. Per-lesson audit data: `interactivity-audit.json`.
> Judge rationale: `INTERACTIVITY-COUNCIL-VERDICTS.md`.

## Interaction model

A retrofitted lesson keeps the existing two-phase Teach-then-Design contract but the Teach phase becomes learner-paced and generative. The SystemDesignLessonPlayer auto-segments any teach over ~500 words on H2/H3 boundaries into 2-4 sections with a continue affordance and persisted position (resolution of the judge conflict on segmenting: it is a player feature plus a markdown accordion pattern for reference-sheet lessons like sd-l0-template-pitfalls and sd-l0-latency-numbers, never a JSON widget and never a lesson split, which would break the lesson-count and spaced-repetition contracts). SableTutor stays aware of which sections are revealed. Inside each 250-300 word concept chunk, `check` fences provide retrieval practice at 3-4 per 1,000 teach words: misconception checks sit BEFORE the paragraph that resolves them, so the learner commits a prediction and experiences the correction (pretesting placement, per the learning-science verdict); consolidation checks sit after their chunk; one cumulative check closes the teach as the bridge into the unchanged free-text design write. Checks are zero-stakes, ungated, retryable, with immediate explanatory feedback that names why the wrong answer is tempting.

Where a lesson's core mechanism is temporal or manipulable, exactly one sim or animated widget replaces the ASCII fence at the mechanism's heart (the one-diagram-per-lesson rule extends to: at most one sim OR animated widget per lesson, plus checks). Every hands-on sim follows a schema-mandated ramp: a one-tap predictPrompt renders before the first animation frame, a worked-example script plays before free manipulation unlocks, then variables unlock one at a time with a single causal read-out (one chart max). Sequence widgets are learner-stepped, never autoplay, with lanes per actor, per-step state annotations, authorable failure toggles (drop message, crash node, timeout), and an optional predict-next-step prompt. Target interaction is 60-90 seconds; the widget is a beat inside the teach, not a destination. Reduced-motion renders discrete state swaps and final-state stills with the widget fully functional, and a single polite aria-live region narrates every state change as text with the SVG presentational.

Architecturally there are two fences on one shared plumbing layer (engineering's resolution, adopted): ```csdiagram keeps stateless staged statics and gains the SD types (topology, ladder; table and er reused as-is), while a new ```cswidget fence carries all stateful interactives (check, sequence, calc engine, sims, steps) in its own zod discriminated union, dispatched through a lazily loaded WidgetFrame that owns the a11y shell. Everything is pure client state: no server routes, no Firestore writes, lessons stay ungated; a lightweight check-attempt analytics event through the existing tutorial progress sync arrives as a late-phase item to feed the WCSR pitch evidence.

### Widget specs

#### `check` [P0] Predict-then-reveal Check (check, M, serves 211)

Fence-driven retrieval widget with two kinds: predict (MCQ, 2-5 options, exactly one correct, mandatory per-option feedback text) and classify (2-3 buckets, items with bucket assignments). Config: { kind, prompt, options?, buckets?, items?, reveal? }, superRefined kind-conditionally. Core interactions: commit an answer, get immediate explanatory feedback confronting the named misconception, retry freely; focus moves to feedback on reveal. Serves 211 lessons (152 high-value); every bolded Interview nuance block is a ready-made check in four formats (predict-the-outcome, classify-the-statement, pick-the-best-move, spot-the-flaw). Resolution recorded: schema-compat (L6) is authored as a check series (predict which reader/writer pairs break per compatibility mode, then reveal deploy order) rather than a sim, per the 2-of-3 judge majority. Ships first: the only widget that moves WCSR at curriculum scale before launch.

#### `segmenting` [P0] Player-level Progressive Disclosure (segmenting, M, serves 208)

NOT a JSON widget (all three judges converged; conflict on layer resolved by doing both): (a) SystemDesignLessonPlayer auto-splits teaches over ~500 words on H2/H3 boundaries into 2-4 learner-advanced sections with a continue affordance and persisted position, fixing pacing across all ~208 lessons with zero re-authoring; (b) a markdown accordion/details pattern in markdownComponents for reference-sheet lessons (sd-l0-template-pitfalls six lists, sd-l0-latency-numbers tables) so they read as retrievable cards. Never split lessons into more lessons (breaks lesson-count and SR contracts). SableTutor must know which sections are revealed.

#### `capacity-calc` [P0] Formula-Slider Calc Engine (hands-on-sim, M, serves 22)

Config-driven formula engine: fence JSON declares inputs (1-6 sliders with min/max/step/scale linear|log/unit, plus select inputs), outputs (1-6, expr in a whitelisted arithmetic mini-grammar parsed by an owned ~80-line recursive-descent evaluator validated at parse time, optional sparkline plot), narrative. Core interactions: drag one slider at a time (staged unlock), watch derived outputs and one sparkline recompute live, switch mode via select. Absorbs as authored presets (resolution, all judges): availability-calc (serial ceiling, 1-(1-a)^n), burn-rate (SLO to depletion), tail-latency-explorer (1-(1-p)^N, p99 becomes p82), utilization-curve (1/(1-rho)), erasure-coding overhead (k/m), and fan-out (followers slider + push/pull/hybrid select showing 250 to 50k write QPS; resolved as a calc preset per engineering over a separate fanout widget, with product's demo value preserved in the authored sd-l0-qps-read-write and sd-l10-news-feed instances). ann-tuning survives only as authored illustrative curves with a mandatory 'illustrative, not measured' label (resolution of product's correctness objection). The L0 estimation module IS this widget. 15 direct lessons plus ~7 preset lessons.

Libraries: none (owned expression evaluator; expr-eval dependency explicitly rejected)

#### `hash-ring` [P0] Consistent Hashing Ring (hands-on-sim, M, serves 4)

THE demo moment (product's named pitch centerpiece; anchors P0 despite reach of 4). Core interactions: add/remove a node under mod-N and watch most keys shatter and remap versus ~1/N on the ring (live percent-remapped read-out), toggle virtual nodes to smooth load distribution. Config: node count, key count (deterministic seeded key set), initial mode, vnode factor. Serves sd-l3-consistent-hashing (the widget IS the lesson), L4 sticky routing, L6 partitioning remap, L10 case studies. Ten-second legible to a non-technical judge; fully client-side and hotspot-safe.

#### `sequence` [P1] Sequence Stepper with Failure Toggles (animated-diagram, L, serves 77)

The workhorse for all temporal mechanisms (77 lessons, 53 high-value: DNS, TCP/TLS, idempotency, dual-write races, sagas, consensus, coordinator crashes, OAuth/PKCE). Config: actors (2-6), steps (2-30: from/to/label/kind request|response|event|timer|note, status ok|lost|late|error, optional per-step shared-state map, when toggleRef with ! negation), toggles (max 3), caption. Core interactions: learner-stepped Prev/Next (never autoplay), flip a failure toggle (drop message, crash node, timeout) and step the changed timeline, optional predict-next-step prompt before a step reveals. The per-step state map renders race interleavings with a visible shared-variable row. Absorbs as authored scenarios, not components (resolutions recorded): inventory-race (two buyers, available=1, oversell vs atomic decrement), retry-storm (per-layer retries multiplying 1 into 27, jitter toggle; sequence over calc per 2-of-3 majority), hol-blocking (H1/H2/H3 lanes, drop-a-packet), and the rebac-graph Zanzibar walk (fixed authored tuple chain with an add/remove-tuple toggle; resolves product's no-graph-engine objection while keeping the 2-of-3 modify verdict). L complexity, so P1 per the binding constraint; it is still the second big build after the P0 anchors.

#### `topology` [P1] Staged-Reveal Topology (animated-diagram, M, serves 16)

Constrained staged-reveal box-and-arrow renderer in the csdiagram (static) union. Config: nodes (2-16, kind client|lb|service|db|cache|queue|cdn|zone|external), edges (sync|async|replication), stages (max 8: adds + per-stage justification note), layout lr|tb; deterministic layered layout, no physics, schema-enforced 16-node cap. Core interactions: step through stages, each component appearing with its requirement-tied justification (the L0 dataflow discipline IS this reveal). Resolution recorded: engineering's keep constrained by learning-science and product's modify; author ONLY the ~16 high-value instances, never blanket-replace the 73 ASCII fences (a readable ASCII fence is not the enemy), and the cap plus authored stages is the guard against the banned physics-graph re-entering. Also hosts lsm-write-path and inverted-index staged builds as instances.

#### `ladder` [P1] Ladder/Spectrum Static (animated-diagram, S, serves 6)

One generic staged-reveal ordered-levels static in the csdiagram union with a log-scale option and per-band annotations. Core interactions: staged reveal per band, optional annotation toggle (what each level shares/costs). Absorbs four slugs as instances (all judges converged): latency-ladder (fixes a named L0 worst lesson; RAM-to-SSD and DC-to-region cliffs seen, not read), consistency spectrum (L5), isolation-spectrum (L10 code-sandbox, replacing a 147-word paragraph), and the L7 burn-rate/DR ladders. phase-clock is cut as a slug (2-of-3); a markdown table covers it.

#### `queue-sim` [P1] Producer/Consumer Queue Sim (hands-on-sim, M, serves 12)

Deterministic producer/consumer stepper. Core interactions: drag producer and consumer rate sliders, toggle bounded vs unbounded queue (watch unbounded OOM vs bounded backpressure), select shed policy (drop-stale, priority, deadline); depth-over-time is the single read-out. Config: rates, capacity, policy set, seeded arrival pattern. Serves 12 lessons across L1/L4/L6/L9 including the recurring scale-on-backlog-not-CPU argument (KEDA-style leading-signal scaling as a mode).

#### `cache-sim` [P1] LRU Cache & Stampede Sim (hands-on-sim, M, serves 4)

Seeded request stream against a small LRU. Core interactions: watch hit/miss/eviction animate with hit-ratio-over-time as the read-out, turn the TTL knob, flip the stampede toggle (hot key expires under load, concurrent DB rebuilds pile up, then enable coalescing/early-refresh). Config: cache size, TTL, stream seed, stampede scenario. 4 of 4 lessons high-value; direct fit for the flagged-worst L1 cdn-caching-foundations and L3 stampede lessons.

#### `rate-limiter` [P1] Rate-Limit Algorithm Comparator (hands-on-sim, M, serves 4)

Token bucket vs fixed window vs sliding-window counter over one deterministic request stream. Core interactions: select algorithm, fire the burst toggle (the fixed-window 2x boundary burst is the predicted-then-violated aha), adjust bucket/window parameters one at a time. Config: algorithms enabled, stream seed, burst timing. Serves L1 admission control, L4 rate-limit-algorithms (the widget IS the lesson), L8 DDoS, and upgrades sd-l10-rate-limiter's 164-word algorithm paragraph.

#### `quorum-explorer` [P1] N/R/W Quorum Explorer (hands-on-sim, M, serves 5)

N/R/W sliders with a kill-a-replica button. Core interactions: set N/R/W and see the overlap guarantee or stale-read window (directly confronting the R+W>N-equals-linearizability misconception), kill replicas and watch write availability change. Absorbs two slugs as configs (resolution, all judges): the Kafka acks/min.insync.replicas/RF relabeled instance for sd-l6-kafka-internals (kill a broker, see whether acked writes survive), and a BFT 3f+1 overlap preset replacing the quorum-overlap slug (cut as standalone). Pure overlap math, table-driven testable.

#### `partition-sim` [P1] Partition & Divergence Sim (hands-on-sim, L, serves 7)

The anchor of L5 theory and the largest single sim build (L; scoped by engineering to exactly 2 replicas plus clients). Core interactions: toggle a partition, issue writes to both sides, choose CP (minority refuses) or AP (both accept, diverge), heal and watch reconciliation: LWW silently dropping a write vs version-vector/CRDT merge (PN-Counter and set union with deterministic baked merge results). Config: mode set, scripted write choices, merge strategy. The learner generating the divergence themselves is textbook generation effect; makes pick-2-of-3 CAP tangible. Serves 7 lessons across L3/L5 (replication-topologies multi-leader conflicts, cap-correct, crdts).

#### `replication-lag` [P1] Replication Lag & Read-Your-Writes (hands-on-sim, M, serves 7)

Leader streaming its log to followers with visible per-follower lag. Core interactions: fire a write burst and watch lag spike, then the read-your-writes scenario: post a comment, read from a lagging replica, watch it vanish, enable sticky routing or a version token and watch it cured. Config: follower count, lag profile, cure mode. The L3 module's stated central mental model; reused directly in L5 session-guarantees. The vanishing-comment moment is a strong prediction-violation event.

#### `watermark-sim` [P1] Event-Time Watermark Sim (hands-on-sim, M, serves 5)

One event-time widget, per-lesson configs (resolution: absorbs watermark-window as an L9 config with processing-time mode and lateness slider; stream-windows is cut as a separate build, with a window-type selector frame included only if trivially cheap). Core interactions: watch out-of-order events land on a timeline as the watermark advances and windows fire, tune the allowed-lateness bound and watch the latency-vs-completeness trade, flip the late-event toggle (re-fire correction vs side output vs wrong-bucket in processing-time mode). Config: seeded event stream, window type, lateness, mode. Serves L6 stream-processing, L9 batch-streaming, L10 ad-click-aggregator, L11 streaming analytics.

#### `shuffle-shard-sim` [P1] Shuffle Sharding Explorer (hands-on-sim, M, serves 2)

N workers, k picks per tenant. Core interactions: flood/poison one tenant and see exactly which other tenants lose capacity under plain sharding vs shuffle sharding, adjust N and k and watch the live full-overlap probability. Config: N, k, tenant count, seeded assignments. Only 2 lessons but both flagged-worst (sd-l4-cell-shuffle-sharding, sd-l7-blast-radius-cells) and the audit calls the combinatorics nearly impossible to feel without manipulation; no other widget covers it. Overlap probability is a pure function with table-driven tests.

Core interactions: staged highlight of the contiguous run or query slice. Serves the three worst L2 lessons (indexing-cost, wide-column, access-pattern-modeling) plus three more. Near-zero marginal build; author before new code where possible.

## Phasing (iteration-sized, each independently shippable)

- Generalize lib/tutorials/diagrams/extract.ts to extractFenceSources(markdown, label) without changing csdiagram behavior
- Create the cswidget zod discriminated union scaffold as per-family schema files composed into one union, mirroring lib/tutorials/diagrams/schema.ts (superRefine on the wrapper, never-throw parse)

## Authoring rules (binding)

- No em dashes anywhere learner-visible: lesson prose, widget labels, captions, prompts, feedback text, aria-live strings.
- All interactivity is fence-driven JSON: csdiagram for stateless staged statics, cswidget for stateful interactives; specs are data, not code (calc expressions use only the whitelisted arithmetic mini-grammar; unknown identifiers fail at parse time).
- Fence hygiene (carried from csdiagram hazards): fence on its own line after a complete paragraph, backticks escaped inside TS template literals, single quotes inside JSON strings, instances generated via the stringify script; a mid-sentence fence swallows prose and fails CI.
- Predict-before-reveal ordering: misconception checks sit BEFORE the paragraph that resolves them; consolidation checks after their chunk; one cumulative check at teach end bridging into the design write.
- Check dosage: 3-4 per 1,000 teach words (one per 250-300 word concept chunk); every check targets a NAMED misconception; feedback is immediate, explanatory (why the wrong answer is tempting), zero stakes, no gating, retry allowed.
- Every hands-on sim opens with a schema-mandated predictPrompt shown before the first animation frame, plays a worked-example script before free manipulation unlocks, and unlocks one variable at a time (staged unlock).
- One causal read-out per sim, max one chart; target 60-90 seconds of interaction; no autoplay loops; sequence widgets are learner-stepped; reset always visible.
- Reduced-motion parity is mandatory: transitions become instant state swaps, animations render final states as stills, sims remain fully functional; status is never encoded by color alone (icon/pattern plus word, e.g. dashed + 'dropped').
- Determinism enforced by test: any randomness must be seeded from the spec so render assertions are stable.
- Density cap (extends the one-diagram-per-lesson rule): at most one sim OR animated widget per lesson, plus checks; the check rollout must not turn teaches into widget walls.
- Reach threshold: new widget types require 3+ lessons served or an explicit pitch justification; otherwise author as a config of an existing engine (check, sequence, calc, steps, ladder, topology).
- Review question before any widget merges: what decision does the learner make inside this widget, and what misconception does it confront? If the answer is none, it is a static or a check, not a sim.
- Segment within the player, never by splitting lessons into more lessons (protects the lesson-count and spaced-repetition contracts).
- Topology stays constrained: schema-capped at 16 nodes, authored stages with per-stage justification, deterministic layout; no free-form graph editing anywhere (standing no-physics-graph and no-Mermaid verdicts remain binding).
- All widget state is client-side: no server routes, no Firestore writes from widgets; checks are ungraded; the analytics event is fire-and-forget through the existing progress sync.
- No live algorithm engines in scripted widgets: concurrent-edit merges, order-book fills, and ANN curves are baked into the spec; ANN curves must carry an explicit 'illustrative, not measured' label.
- The eight pedagogy-final cuts stay cut (abr-sim, compression-bits, hash-chain, sharded-counter, board-zones, stream-windows, merkle-diff, graph-traversal); do not resurrect without post-launch engagement evidence.
- A readable ASCII fence is not the enemy; replace ASCII only where a kept widget or authored instance genuinely upgrades the mental model (roughly the 16 high-value topology cases, not all 73).

## Risks

- Single-lesson tail scope creep is where this project dies: 35+ cut slugs each tempt a bespoke build for 1 lesson. Resolution recorded: product's frozen-backlog rule is binding for COMPONENTS; the steps/sequence/calc engines may absorb tail slugs as authored CONFIGS (learning-science and engineering majority), with instance authoring gated by worst-lesson leverage now and engagement data post-launch.
- Correctness-risk widgets can actively teach wrong intuitions: a toy OT/CRDT that converges incorrectly, a faked ANN recall surface, a buggy matching engine. Resolution: product's veto is binding on live engines; these ship only as scripted replays with baked outcomes, and ann-tuning curves must be labeled illustrative or fall back to a static plus a check.
- Seductive-detail regression: framer-motion makes decoration cheap, and the 8 pedagogy-final cuts (abr-sim, compression-bits, hash-chain, sharded-counter, board-zones, stream-windows, merkle-diff, graph-traversal) will be re-proposed during authoring. The review question and the reach threshold are the guardrails; these cuts are final per the synthesis constraint.
- Topology is the banned physics-graph re-entering through the back door if the schema loosens: the 16-node cap, authored stages, and deterministic layout must live in zod (schema-enforced), not in the authoring guide, and authoring stays restricted to the ~16 high-value instances.
- Bundle tax on unrelated paths: CsDiagram is imported eagerly into shared markdownComponents today, so 25 new components loaded the same way would slow every /learn page including SQL/Python. The cswidget dispatch must stay behind next/dynamic, parsing stays eager for instant validation and CLS-safe placeholders, and the widget chunk splits sims from checks if it exceeds roughly 40KB gzipped; verify bundle size in Iteration 1 and again after Iteration 9.
- Sequence schema under-design bounces absorbed slugs back as bespoke builds: if the schema cannot express interleavings (per-step shared-state map), failure toggles, and multi-lane comparisons, then inventory-race, retry-storm, hol-blocking, and the rebac walk each become new components. Mitigation: design and validate the schema against those four scenarios before building the renderer (Iteration 6 work item).
- Check quality drift at 211-lesson scale: mechanical authoring can degrade checks into recall trivia that skip the misconception. Mitigation: every check must map to a named misconception (review rule), and the Iteration 12 analytics event surfaces answer distributions so ineffective checks get revised with data.
- Widget-wall pacing risk: checks plus a sim plus segmenting could turn a 600-word teach into an interaction gauntlet. The density cap (one sim or animated widget per lesson plus dosed checks) is enforced by a CI test in Iteration 12, not by goodwill.
- Timeline collision with the Aug 25 launch window and the August Gemini Flash migration: the check-first ordering is deliberate so that if later iterations slip, the shipped prefix (checks in the misconception-dense levels, segmenting, calc, hash-ring demo playlist) still moves WCSR and fully stocks the pitch demo; iterations are independently committable for exactly this reason.
- A11y and determinism regressions at scale: 20+ interactive components hand-rolling their own inputs would fragment keyboard/screen-reader behavior. WidgetFrame owns the contract (native inputs, single aria-live channel, SVG presentational, reduced-motion parity) and lands in Iteration 1 BEFORE any widget, with the extended content-integrity gate and seeded-determinism rule active before any authoring merges.
- Fan-out demo value depends on an engine preset: folding fanout-explorer/fanout-sim into capacity-calc (engineering's economy, adopted over learning-science's separate build) risks a dry rendering of product's most judge-legible story (250 to 50k QPS). If the authored instances underperform at demo rehearsal, revisit a dedicated skin as a P2 item; record that this is the one resolution taken against a judge's keep on demo-value grounds.
